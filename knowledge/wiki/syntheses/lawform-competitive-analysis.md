## 1. 로폼 해부

로폼은 **2개 제품 라인**으로 구성된다 **[EXTRACTED]**:

| 라인 | 타깃 | 핵심 기능 |
|---|---|---|
| **로폼 비즈니스** | 기업 **법무팀**(in-house counsel) | 계약 AI 생성·검토, CLM(계약 전주기), 컴플라이언스 에이전트, ERP/결재/SSO/DRM 연동 |
| **로폼 플랜** | 개인·1인 | 문서 자동생성, 전자서명, 클라우드 보관 |

**로폼 비즈니스 4대 기능** **[EXTRACTED]**:
1. 계약관리 에이전트 — 자연어 한 번에 계약 초안 생성(기업 표준계약서 기반)
2. 컴플라이언스 에이전트 — 조직 컴플라이언스 자동 적용, 데이터 연동 자동입력
3. 워크플로우 통합 — 계약 상태·기한 대시보드, 전자서명, 법령캘린더, 송무
4. 전사 통합 — ERP·결재·재무·인사·SSO·DRM 연동

**해자(moat)** **[EXTRACTED]**: 자체 생성형 AI(법률문서 자동작성 특허), 요건사실 그래프 DB(500만건+), "Legal Logic core"(요건·효과 구조판단→재현성), 클라우드 SaaS 구독.

## 2. 결정적 통찰 — 로폼은 소형 "로펌"을 노리지 않는다 **[INFERRED]**

로폼 비즈니스의 워크플로우는 **계약(contract) 중심·기업 내부용**이다. 계열사·ERP·SSO 연동은 **중견·대기업 법무팀** 시그널. 로폼 플랜은 **개인**용. → **변호사가 의뢰인을 대리하는 소형 법무법인(2~15인)의 핵심 워크플로우(=사건/송무 중심)는 두 라인 모두의 사각지대.**

| 축 | 로폼 | 소형 로펌의 실제 업무 |
|---|---|---|
| 단위 | 계약(contract) | **사건(case/matter)** |
| 사용자 | 기업 법무담당·개인 | 변호사 + 사무장 |
| 핵심 리스크 | 계약 컴플라이언스 | **기일·시효 누락**(징계·손배), **이해충돌**(윤리위반) |
| 배포 | 클라우드 구독 | 의뢰인 기밀 → **사내 self-host 선호** |

→ **로폼과 정면충돌(계약생성·CLM·생성형)을 피하고, 사건/송무 축에서 in-house 완성형으로 들어간다.** 우리 [[positioning-legal]] 카테고리("환각 없는 사내 법률지식 검색")와 정합.

## 3. 차별화 매핑 (경쟁 회피 + in-house 완성형)

| 항목 | 로폼 | 우리 |
|---|---|---|
| 형태 | 클라우드 구독(월정액·per-user) | **일회성 구축 + self-host**(종량과금 0) |
| AI | 생성형(특허) | **검색·인용형**(환각경로 없음, 정직) |
| 데이터 | 클라우드 전송 | **사내망 격리**(PIPA·변호사법 §26) |
| 범위 | 계약 전주기 | **사건 전주기**(인테이크→기일→문서→판례) |
| 충돌 | — | 계약생성/CLM 비경쟁 — 사건축으로 우회 |

## 4. 소형 로펌 killer-app 도출 (이미 보유 vs 신규)

**이미 보유**(legal-pro / lawfirm-demo): 사건관리 CRUD(legal-case·case-party·case-document 쓰기), 판례 RAG 검색+원문보기. → 중복 금지.

**신규 killer-app 후보** (pain·차별·복리 기준):

| # | killer-app | pain | 우리 강점 적합 | 신규 인프라 | 우선 |
|---|---|---|---|---|---|
| **K1** | **기일·기한 가디언** (court date / 시효 / 서면제출 기한 추적·알림) | **최상** — 누락 시 변호사 징계·손배. 소형일수록 전담 부재 | business-system entity 확장(legal-case 자식). 캘린더+임박 알림 | 낮음(entity+화면) | **1순위** |
| **K2** | **이해충돌 검사** (수임 전 상대방·관계자 ↔ 기존 의뢰인 충돌 검색) | 높음 — 변호사법 윤리 의무, 수임마다 발생 | **검색엔진 직접 재활용**(이름+의미). self-host=기밀 보장 차별 극대화 | 낮음(search-similar 재사용) | **2순위** |
| **K3** | 수임료 타임시트·빌링 | 중 — 매출 핵심이나 회계SW 대체재 존재 | business-system entity | 중 | 3순위 |
| **K4** | 서면 초안 어시스트(과거 유사서면 **검색**·재활용, 생성 아님) | 중 | 검색형(정직), case-document 재활용 | 중 | 3순위 |

**K1·K2가 killer**: ① 로폼 미커버(사건축) ② 우리 기존 축(entity CRUD + project.search-similar) 재활용 → 신규 인프라 최소 ③ self-host·정직 스토리와 정합 ④ 변호사 최대 리스크(기일누락·이해충돌) 직격.

## 5. 데모 추가 제안 — 복리 매핑

- **K1 기일 가디언**: `deadline`(또는 `case-deadline`) entity를 `presets/ddl/augments/legal/`에 신규 → catalog 환류 → lawfirm-demo/legal-pro 도메인에 추가. 프론트는 vanilla-htmx 리스트+임박 하이라이트(기존 toolbar search 복리). **8번째 축(theme) 아닌 business-system 정공법.**
- **K2 이해충돌**: `project.search-similar` 와이어키를 case-party 대상으로 재사용 → 신규 와이어키 불필요(또는 `party.conflict-check` 추가 검토). embed 사이드카(legal-rag embed-adapter) 재활용.
- 둘 다 데모 포털 카드로 노출 → 소형 로펌 데모 서사 "사건 등록→기일 자동추적→수임 전 충돌검사→판례검색" 완결.

## 6. 정직성 가드 (금지 표현 계승, [[positioning-legal]] §6)

- K1: "기한 누락 100% 방지" 금지 → "등록된 기일의 임박 알림" (입력 의존 명시).
- K2: "이해충돌 완전 검출" 금지 → "기존 의뢰인·당사자 중 유사 이름/관계 후보 제시, 최종 판단은 변호사".
- K4: "서면 자동작성" 금지(로폼 생성형과 혼동·법률서비스법) → "과거 유사 서면 검색·재활용".
