# Supabase RLS Policy Guide

> Copy-paste SQL templates for enabling Row Level Security on catalog entities.
> Per-entity DDL is generated by `scripts/workflow/render.py` + dialect adapters.
> This guide covers the Supabase-specific column defaults and RLS starter policies.

## Per-Table Column Defaults

Every catalog entity table should include these Postgres columns. The supabase
adapter's `SupabaseEntityStore.create()` does NOT send `id`, `created_at`, or
`updated_at` in the request body — Postgres populates them via defaults.

```sql
-- Required server-populated columns (add to every entity table)
id         uuid        NOT NULL DEFAULT gen_random_uuid() PRIMARY KEY,
created_at timestamptz NOT NULL DEFAULT now(),
updated_at timestamptz NOT NULL DEFAULT now()
```

For `updated_at` to stay current on every PATCH, attach a trigger:

```sql
-- Trigger function (create once per database)
CREATE OR REPLACE FUNCTION set_updated_at()
RETURNS TRIGGER AS $$
BEGIN
  NEW.updated_at = now();
  RETURN NEW;
END;
$$ LANGUAGE plpgsql;

-- Attach to each entity table (repeat per table, substituting <table_name>)
CREATE TRIGGER trg_<table_name>_updated_at
  BEFORE UPDATE ON <table_name>
  FOR EACH ROW EXECUTE FUNCTION set_updated_at();
```

## Enabling Row Level Security

```sql
-- Enable RLS on a table
ALTER TABLE <table_name> ENABLE ROW LEVEL SECURITY;

-- service_role bypass: Supabase service_role key bypasses RLS by default.
-- No additional policy needed for service_role.
-- The supabase adapter uses service_role on the server side — all CRUD ops
-- bypass RLS automatically. This is intentional for the M1 demo tier.
-- In M5 multi-tenant mode, replace service_role with per-user JWTs and
-- add tenant_id-scoped policies (see docs/architecture/swappable-layers.md §M5).

-- Anon read policy example (optional — enable if you want public read access)
CREATE POLICY "anon_read_<table_name>"
  ON <table_name>
  FOR SELECT
  TO anon
  USING (true);

-- Authenticated user owns their rows (example pattern for M5 multi-tenant)
-- Requires: tenant_id uuid column + auth.uid() mapped to a tenant
-- CREATE POLICY "tenant_isolation_<table_name>"

--   FOR ALL
--   TO authenticated
--   USING (tenant_id = current_setting('app.current_tenant')::uuid)
--   WITH CHECK (tenant_id = current_setting('app.current_tenant')::uuid);
```

## Example: hr_employee Table

```sql
CREATE TABLE hr_employee (
  id              uuid        NOT NULL DEFAULT gen_random_uuid() PRIMARY KEY,
  created_at      timestamptz NOT NULL DEFAULT now(),
  updated_at      timestamptz NOT NULL DEFAULT now(),
  employee_number varchar(64) NOT NULL UNIQUE,
  full_name       text        NOT NULL,
  department_id   uuid        NOT NULL REFERENCES hr_department(id) ON DELETE RESTRICT,
  position_id     uuid             NULL REFERENCES hr_position(id)  ON DELETE SET NULL,
  hire_date       date        NOT NULL,
  status          text        NOT NULL CHECK (status IN ('active', 'on-leave', 'terminated'))
);

ALTER TABLE hr_employee ENABLE ROW LEVEL SECURITY;

CREATE TRIGGER trg_hr_employee_updated_at
  BEFORE UPDATE ON hr_employee
  FOR EACH ROW EXECUTE FUNCTION set_updated_at();
```

## Applying to All Catalog Entities

Run `python scripts/workflow/render.py --profile <slug> --dialect supabase` (M1+
milestone task — dialect adapter for Supabase-flavoured Postgres). Until the
dialect adapter exists, apply the column defaults and triggers manually per table
using the templates above, substituting the `table:` name from `catalog.yaml`.

## Open Loops

- RLS policies above cover anon read only. Per-user write policies require GoTrue
  JWT integration (deferred to M5 per `docs/business/revenue-roadmap.md`).
- `set_updated_at()` trigger must be created once per database before table DDL.
- `gen_random_uuid()` requires Postgres 13+ (available on all Supabase plans).
