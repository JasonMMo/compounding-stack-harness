# docs/intake-inbox/ — PII-Free Intake Pipeline Records

## Purpose

This directory holds the **PII-free** output records of the autonomous intake pipeline.
It is committed to the repo and visible in git history.

**Raw PII** (email addresses, company names, free-text pain descriptions, revision JSON)
**never** enters this directory. Raw PII lives exclusively in:
- VPS: `/data/intake/data/clients/<client_id>/` (gitignored, on-VPS only)
- Local: `apps/intake/data-mirror/` (gitignored — see `.gitignore`)

## PII Rule (Non-negotiable)

```
COMMIT = slug + score + gap_category + todo_axis + timestamps only.
PII    = email | company name | free_notes | contact info = VPS + gitignored mirror ONLY.
```

Any violation of this rule must be immediately reverted and the CTO notified.

## Contents

| File / Directory | Description |
|---|---|
| `gap-registry.jsonl` | Append-only: one JSON record per deferred/gap lead. Fields: `{ts, slug, score, gap_category, todo_axis}`. PII-free. |
| `gap-summary.md` | Auto-generated by `scripts/workflow/gap_registry_report.py`. Top growth signals by frequency, PROMOTE flags, scope rejects, closed gaps. |
| `pm-inbox.md` | Human-readable triage queue for PM. Lists pending slugs with status + recommended action. |
| `alerts.md` | Append-only: stall/fail alerts from pipeline monitor. Fields: slug, node, error_class, evidence_path, recommended action. |
| `processed.jsonl` | Append-only: one record per fully-processed lead (ts, slug, status, qualify outcome). Used for idempotency by `intake_sync.py`. |
| `evidence/` | PII-free evidence files from pipeline nodes (stderr tails, HTTP status, report paths). Named `<node>-<slug>-<ts>.txt`. |

## Gap Registry Lifecycle

```
gap recorded -> gap-registry.jsonl append
             -> gap_registry_report.py weekly run
             -> gap-summary.md regenerated
             -> count >= promotion_threshold (default 3)
             -> PROMOTE flag in gap-summary.md
             -> CTO weekly scan
             -> Growth-N created for axis expansion
             -> engineer implements
             -> policy entry marked already_served:true
             -> gap moves to "Recently Closed Gaps" section
             -> future leads in that category no longer flagged
```

## Running the Report

```bash
python scripts/workflow/gap_registry_report.py \
  --registry docs/intake-inbox/gap-registry.jsonl \
  --policy apps/intake/qualification_policy.yaml \
  --out docs/intake-inbox/gap-summary.md
```
