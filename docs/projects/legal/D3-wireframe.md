## 1. 통합 1앱 내러티브 — 탭 전환 동선

법무 통합 제품은 **단일 SPA** 안에서 두 탭이 공존한다.
사건현황 탭과 검색 탭은 독립적이지 않다 — 사건 컨텍스트를 검색 탭으로 전달한다.

```
[로그인 화면]
    │
    ▼  POST /auth/login → JWT
[메인 앱 - 탭 레이아웃]
    ├── [검색 탭]  ←──── 기본 진입 (업무담당자)
    │       │
    │       │ ◀── case_id 자동 주입 (사건현황 → [검색] 클릭)
    │       │
    │   검색창 + 사건 필터 드롭다운
    │       │
    │   POST /search → 인용 카드 목록
    │
    └── [사건현황 탭]  ←── 보조 진입 (CEO, IT담당자)
            │
        GET /cases → 사건 행 목록
            │
        [검색] 버튼 클릭
            │
            └──► switchTab("search") + case_id 주입 → 검색 탭 이동
```

**내러티브 핵심**: 사건현황 탭의 [검색] 버튼은 단순 탭 전환이 아니다. `case_id` 를 검색 패널 드롭다운에 자동 설정하여 사건 스코프 검색으로 진입한다. 이 동선이 두 기능을 "2앱"이 아닌 "1앱"으로 만드는 연결 고리다.

## 2. 디자인 토큰 방향 — legal-pro adapter vs theme 레이어

### 2-1. 권고: theme 레이어 채택 (adapter 분리 불필요)

```
vanilla-htmx (기존 범용 adapter)
    │
    ├── design/tokens/semantic.json  ← 공통 토큰
    │
    └── presets/themes/legal-pro/   ← 법무 전용 theme (NEW)
            ├── tokens.css          ← --lr-navy-*, --lr-gold-* override
            ├── components.css      ← citation-card, ingest-badge 전용 스타일
            └── theme.json          ← theme 메타 (slug, displayName, targetDomain)
```

**이유**: 법무 차별화의 핵심은 레이아웃 구조 변경이 아니라 **색 팔레트 + 특수 컴포넌트(인용 카드, 색인 뱃지)** 두 가지다. adapter 분기(frontend/adapters/legal-pro/)는 레이아웃 wire 자체가 달라질 때 쓴다. 현재 사건현황 탭 = 테이블, 검색 탭 = 카드 목록 구조는 vanilla-htmx adapter 로 충분히 표현된다.

**재사용성**: `presets/themes/legal-pro/` 를 8번째 축(visual-asset) 에 등록하면 다음 버티컬(의료·금융)이 동일한 adapter 에 다른 theme 을 얹어 쓴다. 의료 vertical 은 `presets/themes/medical-pro/` 를 신설하되 citation-card 패턴은 legal-pro 를 참조(문서 청크 인용 구조가 동일하다).

### 2-2. legal-pro theme 핵심 토큰

```css
/* presets/themes/legal-pro/tokens.css */

/* Raw override — 법무 전용 팔레트 */
--lr-navy-900: #0F1729;   /* 최심 강조, 헤더 배경 */
--lr-navy-800: #1A2744;   /* primary action (버튼, 링크, 포커스) */
--lr-navy-700: #243659;   /* hover */
--lr-navy-600: #2E4470;   /* active / pressed */
--lr-navy-100: #E8EDF5;   /* primary-subtle (뱃지 배경) */
--lr-navy-050: #F2F5FA;   /* surface-subtle */
--lr-gold-500: #B8960C;   /* 판례 뱃지 강조 (권위, 절제) */
--lr-gold-100: #FDF8E7;   /* 판례 뱃지 배경 */

/* Semantic 매핑 — 컴포넌트는 이 변수만 사용 */
--color-primary:          var(--lr-navy-800);
--color-primary-hover:    var(--lr-navy-700);
--color-primary-subtle:   var(--lr-navy-100);
--color-badge-precedent-bg: var(--lr-gold-100);
--color-badge-precedent-fg: var(--lr-gold-500);
--color-badge-document-bg:  var(--lr-navy-100);
--color-badge-document-fg:  var(--lr-navy-800);

/* 법무 전용 신규 토큰 */
--lr-auth-strip-height: 3px;  /* 헤더 상단 권위 표시 컬러 스트립 */
--lr-header-bg: var(--lr-navy-900);
```

**다른 vertical 이 차용 시 규칙**: `--lr-*` prefix 는 legal-rag 전용. 의료 vertical 은 `--med-*` prefix 로 신설. Semantic 토큰(`--color-primary` 등)은 동일하게 override — 컴포넌트 CSS 는 수정 없이 theme 만 교체.

### 2-3. 판례 금색 뱃지 대비 주의

`#B8960C` on `#FDF8E7` 실측 전까지 확정 불가. 4.5:1 미달 시 `#92720A` 로 어둡게 조정. engineer 구현 전 WebAIM Contrast Checker 실측 필수.

두 타입이 혼합 목록에 표시될 때 왼쪽 컬러 스트립이 빠른 시각 분류를 돕는다.

**구현 규약:**
- `<details class="details-toggle"><summary>상세 정보</summary>` — HTML 네이티브
- 기본: closed 상태 (다른 페르소나에게는 닫힌 채로 렌더링됨)

**rrf_score = 관련도 관계**: `.relevance-score` 에 표시되는 "관련도 0.87" 과 `.citation-details` 의 `rrf_score: 0.870` 은 동일한 값이다. 업무담당자는 "관련도"로, IT 담당자는 "rrf_score"로 같은 데이터를 본다.

## 23. 다음 버티컬 재사용 가이드 (theme 레이어 확장)

법무 vertical 이 확립한 패턴 중 다음은 직접 재사용 가능:

| 패턴 | 재사용 방법 | 의료 vertical 예시 |
|---|---|---|
| 인용 카드 (citation-card) | 출처 타입만 변경 (판례→논문, 사건문서→진료기록) | `.citation-badge--paper`, `.citation-badge--record` |
| 색인 상태 뱃지 (ingest-badge) | 상태 텍스트만 현지화 | 색인완료→분석완료, 대기중→분석중 |
| 헬스 배너 3상태 | 그대로 재사용 | 동일 |
| 탭 전환 + case_id 주입 패턴 | entity_id 만 변경 | patient_id, contract_id |
| 결과 헤더 Lite 안내 | 문구만 교체 | "진단 추천 없음 — 문헌 검색 전용" |
| Details/summary IT 상세 | 그대로 재사용 | 동일 (chunk 디버그 동일 니즈) |

**theme 신설 규칙**: 다음 vertical 은 `presets/themes/<slug>/tokens.css` 에서 `--color-primary` 와 `--color-badge-*` 만 override 하면 citation-card, ingest-badge, health-banner 의 CSS 수정 없이 다른 인상을 갖는다.
