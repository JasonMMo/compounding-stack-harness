# smallmfg-demo — 도메인 전문가 인터뷰 트랜스크립트

[← demo-video-scenario.md](../demo-video-scenario.md)

> Demo Video **Scene 1** 의 근거 자료. 영상 대본이 "real transcript from an actual agent session — do not fabricate" 를 요구하므로,
> axis-7 `domain-expert-generic` 에이전트가 실제 인터뷰 형식으로 기록한 대화 아티팩트다.
> 이 대화에서 도출된 결과가 `profiles/smallmfg-demo.yaml` 과 **1:1 일치**한다 (말미 요약 블록 참조).
>
> 상대: 직원 약 20명 규모 소형 제조업체 **업무담당자** (총무·인사 겸직, IT 비전문).
> 화면 노출용 하이라이트 라인은 `[★ 온스크린]` 으로 표시 — 촬영팀은 이 6줄을 split-view 좌측에 띄운다.
> 전체 세션은 발췌용으로 모두 수록 (실제 디스커버리의 두서없음을 살림).

## 세션

**전문가AI**: 안녕하세요. 회사 업무 중에 "이건 시스템으로 좀 정리됐으면" 싶은 게 어떤 건지부터 편하게 말씀해 주세요. 전문 용어 안 쓰셔도 됩니다.

**업무담당자**: 어… 저희가 사람이 한 스무 명 좀 안 되거든요. 근데 제가 총무도 보고 인사도 보고 다 하는데, 직원 명단이랑 누가 휴가 썼는지 이런 걸 지금 다 엑셀로 관리하고 있어요. 그리고 공장에 기계들 있잖아요, 그거 점검한 거 수리한 거 그것도 따로 적어두고 있고요. 이게 좀 정신이 없어요.

**[★ 온스크린]** **전문가AI**: 그러면 크게 두 덩어리네요 — **사람(직원·휴가)** 관리하고, **설비(기계 점검·수리)** 관리. 이 두 가지 맞으실까요?

**업무담당자**: 네 맞아요 딱 그거예요. 다른 건 뭐 거래처나 매출 이런 건 사장님이랑 경리 누나가 따로 보셔서, 저는 이 두 개만 되면 살 것 같아요.

> *(에이전트 메모: 영업/재무 도메인은 화자 범위 밖 — profile 에 미포함. hr + asset 두 도메인으로 한정.)*

---

**[★ 온스크린]** **전문가AI**: 좋습니다. 먼저 사람 쪽 여쭐게요. 직원이 스무 명 정도라고 하셨는데, **부서**가 나눠져 있나요? 그리고 직급 같은 건 어떻게 되나요?

**업무담당자**: 부서는 뭐 크진 않은데, 생산팀이 제일 많고요, 품질팀 따로 있고, 저처럼 관리(경영지원) 보는 사람들 몇 명, 영업 두 명. 그 정도예요. 직급은 사원-주임-팀장 이렇게… 뭐 대단한 건 아니고요.

**전문가AI**: 정리하면 **부서**(생산/품질/관리/영업)가 있고, 그 안에 **직위**(사원·주임·팀장)가 있고, 각 **직원**이 어느 부서·직위에 속하는지를 보고 싶으신 거네요.

**업무담당자**: 네네 그거요. 지금은 엑셀에 이름 옆에 부서 적어놓는 식이라, 누가 어느 팀인지 한눈에 안 보여요.

**전문가AI**: 한 가지만 더요 — 직원 중에 지금 재직 중인 사람, 휴직 중인 사람, 그만둔 사람을 구분해서 보고 싶으신 적 있으셨어요?

**업무담당자**: 아 맞다 그거 필요해요. 퇴사자를 그냥 지우면 옛날 기록이 사라지니까 못 지우고, 그렇다고 두면 현재 인원이랑 섞여서… 색칠해서 표시해놓긴 하는데 영 그래요.

> *(에이전트 메모: employee.status = active/on-leave/terminated 로 커버. employee + department + position → hr 도메인.)*

---

**[★ 온스크린]** **전문가AI**: 지금 엑셀이나 그룹웨어로 처리하시는 일 중에서 **가장 불편한 게 뭔가요?** 하나만 꼽으신다면.

**업무담당자**: 음… 솔직히 휴가요. 휴가 신청을 카톡으로 하는 사람도 있고 종이로 내는 사람도 있고, 그걸 제가 엑셀에 옮겨 적어요. 그리고 팀장님 승인받아야 하는데 그게 또 말로 "어 오케이" 이러고 끝나서, 나중에 "내가 언제 승인했냐" 이러면 증거가 없어요.

**전문가AI**: 그러니까 휴가가 **① 신청 → ② 승인 → ③ 기록**이 한 군데서 안 굴러가는 게 문제군요. 휴가 종류는 어떤 게 있나요? 연차 말고도요.

**업무담당자**: 연차 있고요, 아프면 병가, 그리고 가끔 무급으로 쉬는 경우. 그 세 개 정도예요.

**전문가AI**: 승인은 몇 단계인가요? 팀장만 승인하면 끝인가요, 아니면 그 위에 또 결재가 있나요?

**업무담당자**: 보통 팀장이 승인하면 저(인사)한테 넘어와서 제가 최종 확인하는 정도? 위로 더 올라가진 않아요. 사장님까진 안 가요.

**[★ 온스크린]** **전문가AI**: 알겠습니다. 그럼 **휴가 신청**을 만들면, 상태가 "작성 → 승인대기 → 승인/반려" 로 흐르고, **결재선은 팀장 → 인사담당 단순 1단계**로 잡으면 되겠네요. 누가 언제 승인/반려했는지도 같이 남고요.

**업무담당자**: 와 그거면 진짜 좋죠. 그 "누가 언제" 가 남는 게 제일 필요해요.

> *(에이전트 메모: leave-request (leave_type: annual/sick/unpaid, status draft→pending→approved/rejected) → hr-leave 도메인.*
> *승인 흐름은 approval 도메인으로 분리: approval-request(subject=leave-request) / approval-step / approver / approval-decision. 단일 1단계 결재.)*

---

**전문가AI**: 이제 설비 쪽이요. 지금 **보유하신 기계·설비 목록**은 어떻게 관리하세요?

**업무담당자**: 어… 그건 엑셀로 그냥… 기계 이름이랑 몇 호기인지 적어놓은 거밖에 없어요. CNC 몇 대, 프레스 몇 대 이런 식으로요.

**전문가AI**: 설비마다 관리번호나 일련번호(시리얼) 같은 게 붙어 있나요? 그리고 어디에 놓여 있는지(위치)도 적어두시나요?

**업무담당자**: 관리번호는 저희가 자체로 붙여요, CNC-001 이런 식으로. 시리얼은 제조사가 붙인 거 있고요. 위치는… 1공장 2공장 정도? 자세히는 안 적어요.

**전문가AI**: 그리고 설비도 "지금 쓰는 거 / 멈춰있는 거 / 폐기한 거" 처럼 상태가 나뉘나요?

**업무담당자**: 네 가동 중인 거랑 고장나서 세워둔 거랑 구분은 해야죠.

> *(에이전트 메모: asset (asset_number, serial_number, location, status) + asset-category(CNC/프레스 등 분류) → asset 도메인.)*

---

**[★ 온스크린]** **전문가AI**: 마지막으로 핵심인데요 — **설비 점검·수리 이력은 지금 어디에 기록하고 계세요?**

**업무담당자**: 그게 제일 엉망이에요. 점검은 분기마다 돌리는데 기계마다 점검표가 종이로 따로 있고, 수리는 업체 부르면 영수증만 받아서 파일에 꽂아놔요. 그래서 "이 기계 마지막에 언제 봤더라" 가 검색이 안 돼요. 다음 점검일도 제 머리로 기억하는 거라 자꾸 놓쳐요.

**전문가AI**: 그러면 설비 하나하나에 붙는 **유지보수 기록**이 필요하시네요. 기록할 때 그게 **정기 점검**인지 **고장 수리**인지 구분하고, 각 기록에 **다음 점검 예정일**을 넣어두면 "곧 점검할 설비"를 미리 띄울 수 있는데, 이게 원하시던 거 맞나요?

**업무담당자**: 네 바로 그거요!! 다음 점검일만 알람처럼 떠도 절반은 해결돼요.

**전문가AI**: 혹시 설비 감가상각(자산 가치 떨어지는 거 회계 처리)까지 여기서 같이 보셔야 하나요?

**업무담당자**: 아니요 그건 세무사님이 따로 하셔서, 저는 점검·수리 이력만 있으면 돼요.

> *(에이전트 메모: maintenance-record (maintenance_type: inspection/corrective, next_due_date) → asset 도메인.*
> *depreciation-schedule 은 명시적으로 불필요 → 미포함. catalog 에 있어도 큐레이션 단계에서 제외.)*

---

**전문가AI**: 정리해 보겠습니다. 두 영역, 항목으로는 **직원·부서·직위 / 휴가 신청 / 휴가 결재 / 설비·설비분류·유지보수기록** — 이렇게 잡으면 말씀하신 게 다 들어갑니다. 생산 공정 스케줄이나 설비 가동률(OEE) 같은 제조 전용 기능은 지금 요구에 없으셔서 넣지 않았습니다. 나중에 필요해지면 그때 제조업 전용으로 확장하면 됩니다.

**업무담당자**: 네 지금은 이거면 충분해요. 딱 이만큼만요.

**전문가AI**: 좋습니다. 이 내용으로 우리 회사 업무 항목 초안을 만들어 두겠습니다. 검토는 사장님(또는 결정권자)이 하시고, 바로 적용되진 않습니다 — 초안(draft) 상태로 올려두겠습니다.

## → 이 대화에서 도출된 customer profile

> 촬영 시 트랜스크립트(좌) ↔ YAML(우) 를 나란히 보여주기 위한 매핑.
> 아래는 `profiles/smallmfg-demo.yaml` 의 `domains:` 블록과 동일.

```yaml
customer:
  slug: smallmfg-demo
  display: "중소제조 데모"
  status: draft          # 직접 머지 ✗ — 결정권자 검토 후 active

domains:
  - slug: hr             # "사람 관리" — 누가 어느 부서/직위인지
    display: "인사 관리"
    entities: [employee, department, position]
  - slug: hr-leave       # "휴가가 제일 불편" — 신청·근태
    display: "휴가 신청·근태"
    entities: [leave-request]
  - slug: approval       # "누가 언제 승인했는지" — 팀장→인사 1단계 결재
    display: "결재 (휴가 승인)"
    entities: [approval-request, approval-step, approver, approval-decision]
  - slug: asset          # "기계 목록 + 점검/수리 이력"
    display: "설비 관리"
    entities: [asset-category, asset, maintenance-record]
```

**대화 → 항목 추적표** (촬영 콜아웃용)

| 담당자가 말한 것 | 도출된 entity |
|---|---|
| "직원 명단 / 누가 어느 팀인지" | `employee`, `department`, `position` |
| "재직/휴직/퇴사 구분" | `employee.status` (active/on-leave/terminated) |
| "휴가 — 연차/병가/무급" | `leave-request` (leave_type) |
| "팀장 → 인사 승인, 누가 언제" | `approval-request` / `approval-step` / `approver` / `approval-decision` |
| "기계 목록 — CNC-001, 위치, 가동/고장" | `asset` (asset_number, serial_number, location, status), `asset-category` |
| "점검·수리 이력, 다음 점검일" | `maintenance-record` (maintenance_type, next_due_date) |
| "감가상각은 세무사가" | (제외 — `depreciation-schedule` 미포함) |

**총 11개 entity** — Scene 2 의 scaffold 출력 11개와 동일.

> 모든 entity 키는 `presets/ddl/catalog.yaml` 에 실재하는 키만 사용 (phantom 키 없음).
> vertical agent 불필요 — 14 baseline 으로 100% 커버.
