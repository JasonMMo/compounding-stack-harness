## 적용 원칙 (작성·수정 시 반드시 확인)

- **ICP narrowing 반영** — 타겟은 [positioning.md §1](positioning.md) 의 1차 ICP: **IT 도입 여력이 없는 소형 업체·스타트업** (직원 대략 1~30명, 전산팀 없음). "중소·중견" 표현 금지. 중·대형은 타겟 아님.
- **honest-marketing 하드 제약** — live-verified 능력만 카피에 등장한다:
  - 대화(인터뷰) → 당일 화면 초안 (verified)
  - self-host: 데이터가 우리 서버 밖으로 안 나감 (verified)
  - 화면·서버 기술을 골라서 교체 (4-corner verified)
  - **금지**: ops pack / Vault / Keycloak SSO / 감사로그 / 멀티테넌트 / 마켓플레이스 — M2+ 미구현. 한 글자도 카피에 넣지 않는다.
- **CTA = 이메일** — 엔드카드와 일관. 개인 Gmail 금지, `[사업 문의 이메일]` placeholder. (향후 카카오톡 채널 추가 시 이 파일에 변형 추가.)
- **데모 링크** — 아직 미촬영. `[데모 링크]` (3분 풀버전) / `[90초 데모 링크]` (Loom outbound cut) placeholder.

## 1. LinkedIn 포스트 (Hook B 발전)

> **용도**: CEO 명의 게시. 이미지 첨부(데모 썸네일) 권장 — LinkedIn 은 이미지 포함 글을 우선 노출.
> **목표**: 게시 후 72시간 내 qualified inbound 1~3건. 0건이면 outbound 로 전환 (positioning.md §6).

---

전산팀 없는 회사, 사내 시스템은 어떻게 만드시나요?

직원 몇 명 안 되는 회사일수록 답이 똑같습니다. 엑셀 여러 개를 띄워놓고 손으로 옮겨 적고, 제대로 만들려고 외주 견적을 받아보면 수천만 원에 6개월. 결국 다시 엑셀로 돌아옵니다.

저희는 다른 방법을 만들었습니다.

AI 도메인 전문가가 담당자에게 묻습니다. "휴가 신청은 어떻게 처리하세요?" "재고는 어디에 기록하세요?" 이 대화 한 번이면 **그날 안에** 직원 관리, 재고, 영업 같은 업무 화면 초안이 나옵니다. 코드도, 개발자 채용도, 6개월 납기도 없습니다.

데이터는 회사 서버 밖으로 나가지 않습니다. 화면과 서버 기술은 회사가 고를 수 있습니다.

3분짜리 실제 시연 영상을 준비했습니다 → [데모 링크]

관심 있으신 대표님·담당자분은 [사업 문의 이메일] 로 편하게 연락 주세요. 무엇부터 시작할지 같이 정리해 드립니다.

## 3. 커뮤니티 소개글 (Hook D 발전)

> **톤 규칙**: 광고가 아니라 "만든 도구 공유 / 오픈소스 소개". 1인칭 메이커 시점. 판매 문구·가격 언급 최소화. 피드백 요청으로 마무리(커뮤니티 호혜 규범).
> **게시 타이밍**: 데모 영상 공개 + GitHub README embed 완료 후 (링크할 랜딩 자료가 있어야 함).

### 3-1. 디스콰이엇(Disquiet) — 메이커 / 초기 사용자 확보 (1순위)

> **근거**: 디스콰이엇은 IT 프로덕트 메이커가 개발 중인 제품을 직접 소개하고 투표·질문·피드백·초기 사용자 확보를 하는 한국 SNS. ICP(소형 업체·스타트업 운영자, 1인 메이커)가 가장 밀집해 있고, "만든 것 공유" 가 플랫폼의 기본 포맷이라 광고처럼 보이지 않는다. 1차 inbound + 초기 trial 신청자 확보에 가장 효율적.

---

**제목: 전산팀 없는 회사가 사내 시스템을 "당일"에 만드는 도구를 만들었습니다**

직원 몇 명 안 되는 회사에서 일하다 보면, 사내 업무 시스템은 늘 엑셀로 끝납니다. 외주를 알아보면 수천만 원·6개월이라 엄두가 안 나고요.

그래서 AI 도메인 전문가가 담당자와 대화하면 — 휴가 처리는 어떻게 하는지, 재고는 어디 적는지 — 그 대화만으로 당일에 업무 화면 초안이 나오는 self-host 도구를 만들고 있습니다. 데이터는 회사 서버 밖으로 안 나가고, 화면(웹)과 서버(Java/Python)는 골라서 쓸 수 있습니다.

3분 시연 영상입니다 → [데모 링크]

지금은 인사·재고·영업 같은 14개 공통 업무가 동작합니다. 소형 업체·스타트업 운영자분들의 피드백이 가장 필요합니다. "우리 업무도 이렇게 될까?" 궁금하시면 댓글이나 [사업 문의 이메일] 로 편하게요.

### 3-2. OKKY — IT 파트너 / 외부 개발 담당자 진입로 (2순위)

> **근거**: OKKY 는 Java·Spring 중심 한국 개발자 커뮤니티. ICP 의 "IT-담당자 = 외부 IT 파트너" 페르소나(여러 소형 고객사를 대신 관리하는 프리랜서·소형 IT 업체)가 모인다. 이들은 고객사에 도구를 추천하는 채널이 되므로 **간접 lead 소스**. 단, 광고 민감도가 높으므로 철저히 기술·오픈소스 톤으로, scaffold 실행 결과 같은 실물 위주로.

---

**제목: [도구 공유] customer profile YAML 한 장 → DDL + 화면 자동 생성 (self-host, 4-corner pluggable)**

소형 고객사를 여러 곳 맡다 보면 매번 비슷한 CRUD 시스템을 처음부터 짜는 게 일이라, 이걸 줄이려고 만든 도구를 공유합니다.

고객사 업무를 정리한 프로필 한 장을 넣으면 명령 한 번에 DDL과 화면 설계가 나오고, 그대로 동작하는 풀스택이 뜹니다. 프론트(vanilla-htmx / react)와 백엔드(fastapi / springboot)를 조합으로 고를 수 있고, 기존 서버가 Java면 SpringBoot로 얹힙니다. 데이터 구조는 한 곳에만 두고 화면·서버를 갈아끼워도 그대로 갑니다(4계층 자동 테스트로 검증).

전부 self-host라 고객사 데이터가 외부로 안 나가는 점이 소형 고객사 설득에 특히 유리하더군요.
