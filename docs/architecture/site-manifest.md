# Site Manifest — JSON Contract

> `out/<profile>/site-manifest.json` — single source of section and page metadata for landing-astro adapter.
> Generated by `scripts/workflow/site_manifest.py` via `scripts/workflow/scaffold.py` (marketing-site branch).
> Frontend adapter **reads** this; it never reimplements section validation logic.

## 1. Scaffold Branch

`scaffold.py::run_scaffold()` inspects `stack.deliverable_kind` immediately after loading the profile:

```
load_profile(slug)
  └── deliverable_kind = profile["stack"].get("deliverable_kind", "business-system")
      ├── "business-system" (default/absent) → existing entity/DDL/screen-manifest pipeline (unchanged)
      └── "marketing-site" → emit_site_manifest(profile, slug, out_dir) → return
```

The business-system path is **not modified**. Zero regression risk for existing profiles.

## 2. JSON Shape

```json
{
  "slug": "agency-demo",
  "deliverable_kind": "marketing-site",
  "theme": "default",
  "pages": [
    {
      "slug": "home",
      "title": "Home",
      "seo": {
        "title": "Agency Demo — We Build Stunning Sites",
        "description": "Expert web agency...",
        "og_image": "assets/og-home.jpg"
      },
      "sections": [
        {
          "type": "hero",
          "variant": "centered",
          "copy": {
            "headline": "We Build Sites That Convert",
            "subhead": "Full-service web agency for ambitious SMBs."
          },
          "assets": ["assets/hero-bg.jpg"],
          "cta": {
            "label": "Get a Free Quote",
            "href": "/contact"
          }
        },
        {
          "type": "footer",
          "copy": {
            "brand_name": "Agency Demo"
          }
        }
      ]
    }
  ],
  "contact": {
    "enabled": true,
    "fields": ["name", "email", "message"],
    "wire_key": "contact.lead_capture"
  }
}
```

### Top-level fields

| Field | Type | Source | Notes |
|---|---|---|---|
| `slug` | string | `profile.customer.slug` | ASCII slug (G-8) |
| `deliverable_kind` | string | fixed `"marketing-site"` | discriminator for adapter routing |
| `theme` | string | `profile.site.theme` | references `presets/themes/<slug>/` (P2) |
| `pages` | array | `profile.site.pages[]` | ordered list of page descriptors |
| `contact` | object | `profile.site.contact` | present only when `contact.enabled: true` |

### page fields

| Field | Type | Notes |
|---|---|---|
| `slug` | string | ASCII (G-8); used as URL path segment |
| `title` | string | human page title |
| `seo` | object | `title`, `description`, `og_image` (optional) |
| `sections` | array | ordered section descriptors |

### section fields

| Field | Type | Notes |
|---|---|---|
| `type` | string | must exist in `presets/site-sections/catalog.yaml` |
| `variant` | string | optional; must be in catalog `variants` list |
| `copy` | object | key-value copy slots; required slots validated at emit time |
| `assets` | array | optional; asset path refs |
| `cta` | object | optional; `label` + `href` |

### contact block (G-1 invariant)

`contact.wire_key = "contact.lead_capture"` is a **reference** to the middle contract wire key.
`site_manifest.py` does not reimplement the contract — the landing-astro adapter resolves the wire key against `middle/contract/` at build time.

## 3. Section Catalog Relationship

`presets/site-sections/catalog.yaml` is the single source of valid section types.
Format documented in `presets/site-sections/_catalog-format.md`.

`site_manifest.py::validate_site()` enforces at emit time:

| Rule | Error behaviour |
|---|---|
| `page.slug` is ASCII | error (G-8) |
| `section.type` exists in catalog | error |
| `section.type` slug is ASCII | error (G-8) |
| `copy_slots.required` keys all present in `section.copy` | error |
| `section.variant` (if set) is in catalog `variants` | error |
| `site.theme` exists at `presets/themes/<slug>/theme.yaml` | **warning only** (P2 incomplete) |

## 4. Derivation & Storage

- `out/<profile>/site-manifest.json` is a **derived artifact** — `out/` is gitignored.
- No entities, no DDL, no screen-manifest.json are written for marketing-site profiles.
- Regenerate: `python scripts/workflow/scaffold.py --profile agency-demo`.

## 5. Phase Roadmap

| Phase | Dependency on site-manifest |

| P1 (this doc) | schema + validation + emit; `agency-demo.yaml` dogfood |
| P2 | `presets/themes/<slug>/theme.yaml` — theme.yaml existence check promoted from warning to error |
| P3 | `frontend/adapters/landing-astro/` reads site-manifest; sections drive `.astro` component routing |
| P4 | vision-QA gate reads rendered output; G-15 guard added to `scripts/diagnose.py` |
| P5 | intake converts marketing-site answers to `site:` block (same schema) |
