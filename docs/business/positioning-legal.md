## 1. 포지셔닝 스테이트먼트

**한 문장**:
"법무법인 자체 서버에서 돌아가는 판례·사건문서 검색 도구 — 답변마다 출처 문서 번호가 붙어, 외부 유출도 없고 추측도 없다."

### 카테고리 정의

우리는 **"법률 AI 챗봇"이 아니다.** 우리는 **"환각 없는 사내 법률지식 검색 도구"**다.

| 구분 | 로앤비 / Westlaw | ChatGPT / 일반 LLM | 우리 제품 |
|---|---|---|---|
| 판례 DB 범위 | 넓고 체계적, 공식 | 학습 데이터 기반 (불완전) | 귀사 보유 문서 + 판례 선택 탑재 |
| 외부 데이터 전송 | 없음 (구독형 열람) | **전송됨** (클라우드 LLM) | **없음** (사내망 self-host) |
| 환각 위험 | 없음 (DB 조회) | **높음** (생성형 모델) | **없음** (DB PK 인용만) |
| 내 사건 문서 검색 | 불가 | 불가 (보안 위험) | **가능** (귀사 서버 내) |
| 비용 구조 | 연 구독 고정 + per-user | 토큰 종량 (쓸수록 증가) | 구축 일회성 + self-host 서버 실비 |

**경쟁 공백**: 로앤비·Westlaw는 공개 판례 DB에 강하지만 귀사의 사건 문서를 검색하지 못한다. ChatGPT는 사건 문서를 올리면 외부로 전송되고 답변이 그럴듯한 추측일 수 있다. 우리는 그 두 틈새를 메운다.

## 2. 핵심 메시지 3+1

### M1 — 데이터가 사무실 밖으로 나가지 않는다

**헤드라인**: "사건 자료를 AI에 올려도 되나요? — 저희는 서버가 귀사 안에 있습니다."

**근거**:
- 개인정보보호법(PIPA) §23·28·29: 법적 분쟁 관련 개인정보·민감정보는 제3자 클라우드 전송 시 동의·보호조치 의무.
- 법무법인 의뢰인 비밀유지 의무(변호사법 §26): 의뢰 정보 외부 유출은 윤리 위반 가능.
- 우리 제품: 임베딩·검색 전 과정이 귀사 서버 내부에서 실행. 외부 API 호출 없음.

**정직한 단서**: "외부 API 호출 없음"은 검색 단계에 한정된다. 서버 자체(전기·IDC 실비)는 귀사 운영 비용으로 발생한다. AI 답변을 최종 법률 의견서로 사용하는 것은 반드시 변호사가 검토해야 한다.

---

### M2 — 모든 답변에 출처 문서 번호가 붙는다

**헤드라인**: "AI가 틀린 판례를 만들어냈다고요? — 저희는 답변마다 실제 문서 번호를 답니다."

**근거**:
- 구현 방식: postgres tsvector + pgvector 기반 검색 → 검색 결과는 DB 레코드(PK)에 1:1 대응.
- 답변 형식: "판례 2023나12345 (서울고법), holding: …" — 존재하지 않는 판례를 생성하지 않음.
- 생성형 LLM이 없는 검색 전용 경로(Lite 단계)에서 환각 경로 자체가 없음.

**정직한 단서**: "환각 0"은 **검색·인용 단계**에 해당한다. 자연어 질의 해석 단계에서 관련 없는 문서가 상위 노출될 수 있다(검색 정확도 문제 = 다름). 검색 결과의 법률적 해석은 변호사가 수행해야 한다. 상위 옵션(생성형 요약)은 별도이며 현재 제공 계획 없음.

---

### M3 — 쓸수록 비용이 늘지 않는다

**헤드라인**: "직원 10명이 하루 100번 검색해도 추가 청구서가 오지 않습니다."

**근거**:
- 제3자 LLM API 종량 과금 없음 — 검색 쿼리당 API 비용 0.
- 임베딩은 구축 시 1회 실행(판례 1,000건 기준 ~$0.04, 또는 로컬 모델 시 $0).
- 이후 운영 비용 = 서버 전기·인터넷 실비만.

**정직한 단서**: "종량 과금 0"은 제3자 AI API에 한정된다. 귀사 서버 운영비(전기, 인터넷, 하드웨어 유지)는 실비로 발생한다. 구축 일회성 비용은 별도(WTP 인터뷰 후 확정 예정).

---

### M4 — 신입 변호사·사무장 온보딩 속도

**헤드라인**: "3년 차 변호사가 알고 있는 판례, 신입이 5분 만에 찾습니다."

**근거**:
- 사내 판례·사건 문서·계약서 템플릿이 검색 가능한 KB로 구축됨.
- 자연어 질의("이혼 소송에서 재산분할 비율이 문제 된 최근 판례") → 관련 문서 상위 노출.
- 선임 변호사의 암묵지(판례 북마크, 사건 메모)가 팀 공유 자산으로 전환.

**정직한 단서**: 검색 품질은 입력된 문서의 품질·구조화 수준에 비례한다. 스캔본 PDF 등 OCR 미처리 문서는 검색 대상 불가 — 구축 전 문서 현황 점검 필요.

## 3. 타깃 세그먼트 · 페르소나

### 우선 세그먼트: 소형 법무법인 (변호사 2~15인)

**왜 여기가 먼저인가**:
- 판례 DB(로앤비) 구독료 부담은 있으나 대형 LegalTech 도입 예산 없음.
- 전담 IT 인력 없음 → 클라우드 SaaS 도입 시 보안 설정 불안감.
- 의뢰인 기밀유지 의무가 "ChatGPT에 올리면 안 된다"는 인식을 만들어 두었음.
- 사건 수 증가 시 문서 검색 병목이 즉시 발생 → 페인 명확.

### 분야별 우선순위 (문서검색 페인 크기 기준)

| 분야 | 문서 특성 | 검색 페인 | 우선순위 |
|---|---|---|---|
| 민사·가사 | 유형 반복(이혼, 손배), 선례 중요 | 과거 유사 사건 판례 검색 반복 | **1순위** |
| 형사 | 선례 및 수사 기록 | 양형 판례 검색 | **1순위** |
| 기업·계약 | 계약서 템플릿 다수 | 내부 계약 템플릿 재사용 | **2순위** |
| 행정 | 법령·시행령 연동 | 법령 DB 연동 필요 → 복잡도 높음 | **3순위** |

### 도입 트리거 (이 상황이 오면 문의한다)

1. "ChatGPT에 사건 자료 올렸다가 보안팀한테 지적받았다" — PIPA 인식 각성 후.
2. 사무장·신입 변호사 온보딩 중 "판례 어디서 찾나요?" 반복 질문.
3. 파트너 변호사 퇴사 후 암묵지 손실 경험.
4. 로앤비 구독 갱신 시즌에 대안 비교.

### 의사결정자 페르소나

**대표 변호사(파트너)** — 최종 구매 결정.
- 관심사: 기밀유지 리스크, 도입 후 책임, 직원 생산성.
- 언어: "법적으로 문제없나요?", "다른 법무법인에서 쓰나요?", "얼마예요?".
- 채널: 변호사 커뮤니티 구전, 지인 추천.

**사무장(운영 담당)** — 실사용자 + 도입 제안자.
- 관심사: 설치 난이도, 사용 편의성, 유지보수 부담.
- 언어: "IT 몰라도 쓸 수 있나요?", "뭔가 고장나면 누구한테 연락해요?".

## 4. 반론 처리 (Objection Handling)

### "ChatGPT 쓰면 되는데요?"

**정직한 응답**:
ChatGPT는 두 가지 문제가 있습니다. 첫째, 사건 자료를 붙여넣으면 OpenAI 서버로 전송됩니다 — 의뢰인 기밀유지 의무와 PIPA 측면에서 검토가 필요한 부분입니다. 둘째, ChatGPT는 그럴듯한 문장을 만드는 도구이지 판례 DB를 조회하는 도구가 아닙니다 — 존재하지 않는 판례 번호를 자신감 있게 답변하는 사례가 보고되어 있습니다.

저희는 귀사 서버에서 실제 존재하는 문서만 검색하고, 모든 답변에 문서 번호를 붙입니다.

단, ChatGPT처럼 문장을 자동 생성해 드리지는 않습니다 — 저희는 검색 도구입니다. 이 차이가 괜찮다면 저희가 맞을 수 있습니다.

---

### "설치하고 유지보수하는 게 부담스러워요."

**정직한 응답**:
맞습니다, 설치는 필요합니다. 저희가 구축을 담당하고, 초기 세팅(서버 1대, docker 기반)은 저희 쪽에서 진행합니다. 이후 일상 운영(켜고 끄기, 문서 추가)은 별도 IT 지식 없이 가능하도록 설계합니다.

다만 서버 장비가 고장나거나 OS 업데이트가 필요한 경우는 귀사 환경에 따라 대응이 필요할 수 있습니다. 이 부분의 지원 범위와 조건은 계약 전에 명확히 합의합니다.

완전 무관리 SaaS를 원하신다면 저희보다 클라우드형 제품이 맞을 수 있습니다 — 단, 그 경우 데이터 외부 전송 문제를 별도로 검토하셔야 합니다.

---

### "정말 정확한가요? AI가 틀리면 어떡하죠?"

**정직한 응답**:
저희 제품은 생성형 AI가 아닙니다. 질문을 던지면 실제 존재하는 문서 중 관련도 높은 것을 상위에 보여주고, 그 문서 번호(DB PK)를 함께 표시합니다.

"틀린 판례를 만들어내는" 환각은 저희 경로에서 발생하지 않습니다. 다만 관련도 계산이 부정확해서 원하는 판례가 상위에 안 나올 수는 있습니다 — 이건 검색 엔진과 같은 문제입니다(구글도 가끔 엉뚱한 결과를 줍니다).

법률 의견서 최종 판단은 반드시 변호사가 직접 문서를 확인하고 내려야 합니다 — 저희 도구는 그 과정을 빠르게 만드는 것이지 대체하지 않습니다.

---

### "얼마예요?"

**정직한 응답**:
아직 가격을 확정하지 않았습니다. 귀사 규모(변호사 수, 보유 문서량, 서버 환경)에 따라 구축 범위가 달라지기 때문입니다.

저희가 먼저 귀사의 상황을 30분 인터뷰로 파악하고, 구체적인 범위와 비용을 제안드리겠습니다. 인터뷰 자체는 무료이며 아무 의무도 없습니다.

한 가지 말씀드릴 수 있는 것: 이후 제3자 AI API 종량 청구는 없습니다. 구축비 외에 반복 청구 구조가 없습니다(서버 실비 제외).

## 5. 랜딩 / 소개자료 카피 초안

### A안 — 신뢰·안전 우선

**헤드라인**:
"사건 자료를 AI로 검색하고 싶었지만, 외부 유출이 걱정됐다면"

**서브헤드**:
법무법인 서버 안에서만 돌아가는 판례·사건문서 검색 도구입니다.
답변마다 실제 문서 번호가 붙습니다. 추측하지 않습니다.

**CTA**:
"30분 무료 상황 파악 신청하기" → [상담 신청 폼]

**보조 텍스트**:
제3자 AI 서비스로 데이터가 전송되지 않습니다 / 모든 답변은 실제 존재하는 문서에서만 / 설치 후 추가 종량 청구 없음

---

### B안 — 생산성·속도 우선

**헤드라인**:
"신입이 유사 판례 찾는 데 2시간, 선임이 5분인 이유"

**서브헤드**:
선임 변호사의 판례 지식을 팀 전체가 검색할 수 있게 만드는 도구입니다.
귀사 서버에서 돌아가고, 외부로 나가지 않습니다.

**CTA**:
"우리 사무소에 맞는지 확인해 보기" → [상담 신청 폼]

**보조 텍스트**:
귀사 보유 사건문서·판례 대상 / 답변 = 실제 문서 인용, 추측 없음 / 생성형 AI 아님 — 검색 도구

## 6. 금지 표현 목록

아래 표현은 우리 제품·영업 자료 어디에도 사용하지 않는다.

| 금지 표현 | 금지 이유 | 대체 표현 |
|---|---|---|
| "월 비용 0", "운영비 무료" | 서버 실비가 존재함 | "제3자 AI API 종량 과금 없음" |
| "100% 정확", "오류 없음" | 검색 정확도는 문서 품질·쿼리에 따라 달라짐 | "모든 답변에 출처 문서 번호 첨부" |
| "AI 변호사", "AI 법률 자문" | 법률서비스법 위반 가능, 과장 | "법률 문서 검색 도구" |
| "생성형 AI", "ChatGPT 같은" | 제품이 생성형 아님, 혼동 유발 | "검색 + 인용 도구" |
| "환각 완전 제거" | 절대 표현, 검증 불가 | "생성 단계가 없어 환각 경로 없음" |
| "즉시 도입 가능" | 구축·문서 준비 기간 필요 | "구축 일정은 문서 현황 점검 후 협의" |
| "타사 대비 XX% 저렴" | 비교 근거 미확인 | 비교 없이 우리 가치만 설명 |
| "보안 인증 취득" | 인증 없음 | "self-host 구조로 제3자 전송 없음" |
| "AI가 판례 분석해 드립니다" | 분석(해석)은 변호사 업무 | "관련 판례를 찾아 출처와 함께 보여드립니다" |
| "데이터 해킹 불가" | 절대 보장 불가 | "외부 전송 경로 없음, 사내망 격리" |

## 7. PM WTP 킷 정합 메모

이 문서의 핵심 메시지(M1~M3)는 WTP 인터뷰에서 검증해야 할 **가치 가설**과 1:1 대응한다.

| 이 문서의 메시지 | WTP 킷에서 검증할 가설 | 과선점 위험 |
